# 照片删了别慌：reTF 一键恢复教程

> 只用在一种场景：**手机没 root，TF/SD 卡里的照片被删了**，手上只有一部安卓手机 + 一个 OTG 读卡器。
> 全程在 Termux 里敲命令，但**只要会复制粘贴就行**，选项都是输数字。

---

## 一、先搞懂为什么还能救回来

卡里的照片被"删除"时，**照片本身并没有消失**。

删除只是把"目录"这一页撕掉了——卡还在，照片的二进制数据也还躺在原地，只是系统找不到它们了。

所以只要**从现在开始不往卡里写新东西**，把卡原样读一遍、按文件头把照片一张张"抠"出来就行。

> ⚠️ 这是全部前提：**不要再往卡里写任何东西**。写进去就会覆盖掉还没救的照片。

---

## 二、动手前必须做的 4 件事（很重要）

| 要做的事 | 为什么 |
|---|---|
| ① **立刻停止写入**：别开相机、别截图、别下载、别"修复 SD 卡"、别格式化 | 写入会永久覆盖你的照片 |
| ② **别装任何"数据恢复 APP"** | 安装过程本身就在写存储，反而害了你 |
| ③ 装 **Termux** 和 **Termux:API** 两个 App，**从同一个渠道装**（推荐都用 F-Droid） | Google Play 版的 Termux 已停更，和 API 对不上会调不通 |
| ④ 打开手机 **OTG 开关**（小米/红米默认是关的） | 不开 OTG，手机根本看不到读卡器 |

Termux:API 装完后，去手机设置里给它开**自启动 + 关联启动 + 后台运行**权限，否则后面 `termux-usb -l` 会一直卡住或返回空。

## 三、一步安装（复制粘贴这一行）

打开 Termux，把下面这行整个粘进去，回车：

```bash
curl -fsSL -o install.sh https://gcore.jsdelivr.net/gh/riluo-ya/blog@main/sh/reTF/install.sh && bash install.sh
```

它会自动做完这些事，**中途弹窗一律点"允许"**：

1. 装依赖（python、clang、libusb、termux-api、curl）
2. 把所有脚本下载到安装目录
3. 编译核心读卡程序 `scsi_dump`
4. 申请存储权限
5. **装完自动打开主菜单**

> 如果提示 `/retf 不可写`（无 root 时根目录只读，很正常），脚本会自动改成 `~/retf`，功能完全一样，不用管。

## 四、主菜单怎么用

```
  1  查看 USB 设备（termux-usb -l）
  2  读取卡的容量信息
  3  探测是不是扩容卡（省时间）
  4  环境自检
  5  开始 / 继续扫描照片    ★ 主要用这个
  6  整理照片（按拍摄时间重命名）
  7  导出照片到相册 / 自定义目录
  8  清理缓存与临时文件    ★ 腾空间用这个
  9  查看进度
  10 参数设置（含导出目录、每轮大小等）
  11 在线更新脚本
  0  退出
```

**推荐流程：1 → 2 → 3 → 5**（想省事就 1 → 5，脚本会自动测容量）

### 第 1 步：确认手机看到了读卡器（菜单 1）

把 TF 卡插进读卡器、读卡器插手机，选 `1`。

- 显示 `[]`：没识别到，回去查 OTG 开关和硬件，重插一次
- 显示 `["/dev/bus/usb/001/015"]`：识别到了，这个路径就是你的设备号

> **设备号每次重插都可能变**，所以每次操作前都重新看一眼，别照抄别人的数字。

### 第 2 步：看容量（菜单 2）

选 `2`，手机上会弹 USB 授权框，**点"允许"（可以勾选"记住"）**。

看到类似这行就说明链路通了，libusb 已经能读卡：

```
容量: 1048576000 扇区 x 512 字节 = 536.9 GB (500 GiB)
```

> 如果提示"Android 已移除 USB 设备"，这是 libusb 接管设备的正常现象，别慌。

### 第 3 步：探测是不是扩容卡（菜单 3，强烈建议）

扩容卡（虚标容量）超出真实容量的部分，读出来全是错误或垃圾，扫它纯属浪费几小时。

选 `3`，会采样 24 个点打出一张表，最后给结论：

- "全部采样点都能读出" → 真卡，放心扫
- "这是一张扩容卡，真实容量约 XX GiB" → **把给出的 LBA 数字填进菜单 9 的 TOTAL_SECTORS**，只扫这一段就够了

### 第 4 步：扫描（菜单 5）

选 `5`，只会问你两个问题，**其余一路回车用默认**：

1. **每轮扫多少 GB**：默认 `10`，直接回车。手机存储紧张就填小点（比如 `5`）
2. **确认开始**：输 `1`

然后就开始跑了。**扫描期间别锁屏、别拔读卡器。**

扫完一轮（约 14 分钟）会自动抠图 + 按拍摄时间整理好，然后问你：

```
  1 = 继续扫描下一段
  2 = 结束扫描，并把照片移动到手机相册
  3 = 结束扫描，先不移动
```

**每扫完一轮都可以先看效果**：选 `3` 去相册看看照片对不对，觉得够了就选 `2` 一次搬进相册；想接着扫就选 `1`。

中途断了（OTG 掉线、息屏）也**不用从头再来**——进度已经存好了，下次选 `5` 会自动接着扫。

### 第 5 步：导出照片（菜单 7）

选 `7`，它会先问你要不要换目录：

```
  1  系统相册（相机目录）—— /storage/emulated/0/DCIM/Camera
  2  系统相册下新建一个文件夹，比如 reTF已恢复
  3  自己输入一个路径（比如 /storage/emulated/0/DCIM/我的照片、~/Pictures 等）
  0  取消
```

- 想让照片直接出现在手机相册里 → 选 `1` 或 `2`
- 想存到别的地方（比如 `~/Pictures`、SD 卡某个目录）→ 选 `3`，把路径粘进去，**目录不存在会问你要不要自动建**
- 设好后会**记住这个目录**，下次默认还是它；想改随时来菜单 `7` 或 `10`

> 导出是「先复制、复制成功再删原件」，中途失败也不会丢照片。
> 如果提示目录不可写，先执行 `termux-setup-storage` 授予存储权限。

## 四·五、空间不够了？清理缓存（菜单 8）

扫描中途会产生 10G 左右的临时镜像，扫完就自动删，但**中途中断会残留**。手机空间紧张时选 `8`：

```
  1  临时镜像缓存 seg_*.img       ← 最占空间，已抠完图的段删了不影响照片
  2  扫描进度记录                  ← 删掉 = 下次从第 1 段重新开始
  3  未整理的原始文件              ← 编号命名的原始文件，整理完就没用
  4  已整理照片（原始副本）        ← 确认已导出到相册再删
  5  一键清空全部
  0  返回
```

每一项都会**先显示占用多大、删之前再问一次**，不会误删。第 5 项只删数据，**不会删脚本本身**。

---

## 五、以后怎么更新（菜单 11）

脚本更新了不用重装，进主菜单选 `11 在线更新脚本`，它会：

- 从 CDN 重新下载全部 7 个脚本并覆盖
- 源码有变化就自动重新编译 `scsi_dump`
- **保留你的配置、扫描进度和已恢复的照片**

> 下载会先落到临时目录，**全部下完才覆盖**，万一中途断网也不会把现有脚本弄坏。
> 更新完记得**退出重新运行** `main.sh`（它会问你要不要直接退出，默认退出）。
> 正在扫描时先别更新。

---

## 五·五、下载失败？会自动换线路

下载脚本时如果某个线路不通，脚本会**自动换下一个**，不用你管：

1. **jsDelivr 的四个节点**（gcore / cdn / fastly / testingcf）
2. **GitHub 代理镜像**（ghproxy / gh-proxy / gitmirror）
3. **最后才是 GitHub 原生链接**

规则是：**同一个线路试 2 次不行就换下一个**，一路试到最后一个为止。

还有两个细节：

- **会记住上次成功的线路**，下次优先用它，所以通常只有第一个文件需要试，后面的秒下。
- **会校验下载到的内容**。有些镜像会返回 200 但内容其实是 HTML 错误页，脚本会识别出来并换源——不会给你一堆假文件。

> 万一所有线路都失败了，脚本会给出 GitHub 原生链接，可以用浏览器手动下载后放进安装目录。

## 六、视频（AVI / WAV）也能救

脚本已经支持 **AVI 和 WAV**，默认就开着（抠图类型默认 `jpg,png,heic,avi`）。

**原理上比照片还简单**：AVI 和 WAV 都是 RIFF 容器，开头就写明了整个文件多大（`'RIFF' + 长度 + 类型`），能一步算出结尾，不用像 JPEG 那样逐字节找。

**但有三个必须知道的限制：**

1. **大小有上限，默认 120MB。** 视频动辄几百 MB，手机内存扛不住，超过上限的直接跳过不恢复。想改：菜单 `10` → `7`（手机内存小于 4G 建议调到 50）。
2. **长度字段可能被写坏。** 卡删过之后，头部那个长度数字本身可能是脏的，所以脚本会校验：类型必须是 `AVI `/`WAVE`、AVI 后面要跟正常块头、长度不能离谱。校验不过就跳过——宁可漏，也不给你一堆打不开的垃圾文件。
3. **长视频容易跨段被截断。** 默认每 10GB 一段单独处理，视频正好压在段边界上就会被切成两半。真要救长视频，把每段调大（菜单 `10` → `2`，比如填 30）。

**视频不会跟照片混在一起**：整理时照片按拍摄时间进年月文件夹，视频单独进 `已整理/视频/` 目录，保持原文件名（视频里没有拍摄时间可用）。

> 只想要照片、不想扫视频？菜单 `10` → `4`，把 `avi` 去掉就行，扫描快一点、内存也稳一点。

## 七、几个必知的实话

**文件名和文件夹结构救不回来。**
Card 出来的文件是编号的，原文件名（比如 `IMG_0231.jpg`）和目录结构**已经永久丢失**，这是这种技术的固有限制，任何工具都一样。

好消息是 JPEG 里通常还留着**拍摄时间**，脚本会按它重新命名（如 `20240315_142530.jpg`）并按年月分好文件夹，打不开的坏图会被挑到 `_broken/`，太小的缩略图挑到 `_thumbs/`。

**速度参考：** USB 2.0 读卡器约 **12.8 MB/s**，500G 全卡扫完理论要 **11.6 小时**。所以先扫前 20G 看看效果，别一上来就全卡扫。

## 八、出问题了看这里

| 现象 | 原因 / 怎么办 |
|---|---|
| `fd 无效: %d` | 脚本已处理，真遇到就把命令写完整重跑 |
| `No such file or directory` | 路径里别用 `~`，用 `$HOME` 或写全路径（脚本已自动处理） |
| `No such device` | 重插读卡器后设备号会变，回菜单 `1` 重新看 |
| 跑到一半读不出数据 | 小米 OTG 空闲 10 分钟自动关了，去设置里找"永不关闭"，重插再扫 |
| `termux-usb -l` 返回空 / 一直卡住 | Termux:API 没装、渠道不一致，或没给它开后台运行权限 |
| 扫了很久一张图都没有 | 先确认菜单 `2` 能读出容量；再确认照片是不是真的曾在这张卡上 |
| 存储不够 | 菜单 `9` 把 SEG_GB 调小，或清理手机空间 |

**实在看不懂就跑菜单 `4` 环境自检**，缺什么它会直接告诉你。

## 九、常用命令速查

```bash
# 安装（只需跑一次）
curl -fsSL -o install.sh https://gcore.jsdelivr.net/gh/riluo-ya/blog@main/sh/reTF/install.sh && bash install.sh

# 以后想再用，直接打开主菜单
cd ~/retf && bash main.sh        # 装在 ~/retf 的情况
cd /retf  && bash main.sh        # 装在 /retf 的情况
```

> 如果装的时候卡在哪个文件下载失败，多半是 CDN 还没同步新文件，等几分钟再试，或检查网络。
